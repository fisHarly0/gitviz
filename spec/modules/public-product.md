# 公开产品交付验收

目标：让首次接触项目的用户能安装、理解并可靠地使用 Gitviz。用户 2026-10-04 授权开始完善；基线 main / decad8e，工作树干净。沿用三端，不缩减为单一插件或只读工具。

## 交付清单（逐项取得证据后关闭）

- [ ] P1 Git 操作一致性：桌面真实同步 HEAD/index/worktree；创建分支不切换；独立 worktree 保留原目录；恢复生成新提交与备份；三端统一预览、确认、过期状态、脏工作区与失败说明。
- [ ] P1 编辑与恢复：路径边界、符号链接与元数据保护；用户 Git 身份/hooks/signing 生效；编辑缓存和仓库切换不串写；失败不丢内容，有明确继续或恢复路径；操作记录可检查。
- [ ] P2 地图可读性：连续提交折叠、分支/里程碑概览、围绕选中节点探索；完整合并关系与搜索/键盘/缩放保持正确，三端一致。
- [ ] P2 首次使用：明确当前仓库、实际 HEAD 与预览位置；统一可理解的语言、可访问确认与错误态；安装、升级、重启和缺少 Git 可自行解决。
- [ ] P3 工程交付：自动 CI（静态检查、真实 Git 测试、构建）；可复现版本与打包、许可证/贡献/安全反馈说明；准备正式 Release 安装包、校验和与发布说明。
- [ ] P3 发布验证：干净环境安装、升级、三端冒烟与真实复杂历史回归；记录支持平台/限制。发布到外部渠道前，具体版本与产物全部可审查；商店凭据缺失不伪造发布成功。

每批只推进一个模块并保留完整目标。主要测试在 F:/Codex/work/gitviz-product，缓存 F:/dev/cache。禁止在真实用户仓库进行写入测试。既有 10000 条浏览测试不替代真实写入和发布验收。

## 本批：桌面写入契约

替换仅改 HEAD 的 checkout 和无边界的 write_file/add_and_commit。使用 Git CLI 执行分支切换与提交，合并保存为受保护的单一请求，绑定仓库、HEAD、分支和源文件内容。操作前预览与显式确认，后端重复检查；清晰保留失败后的文件、暂存区及备份。读写真实 Git 测试覆盖特殊路径、脏工作区、陈旧请求、hook 失败、身份缺失和正常同步；前端编辑状态随真实 HEAD 更新。
