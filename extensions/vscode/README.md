# Gitviz · 版本树

像游戏存档一样探索真实 Git 历史。提交是节点，分叉是试验线，合并会显示全部父连接。

## 安装与打开

在 VS Code 的扩展菜单选择 **从 VSIX 安装**，选取 `gitviz-0.2.0.vsix`。打开可信任的本地 Git 仓库，然后运行命令 **Gitviz: 打开交互式版本树**，或点击源代码管理标题栏的分支图标。

需要 VS Code 1.90+ 和已安装的 Git。插件没有网络服务或遥测，不需要 API key。

## 操作

- 点击节点：只读预览，不切换工作文件。绿色标出真实 HEAD，琥珀色边框标出当前选择。
- 拖动地图空白处平移，使用右下角缩放、适应窗口；上下方向键选择节点，Home/End 到首尾。
- 搜索本机全部可达历史的提交标题、作者、编号或引用，包括尚未加载的提交；点搜索结果会逐批加载并定位。通过路径筛选突出某条分支的历史。
- “加载更早历史”读取下一批，“连续加载全部”读到末尾；随时停止，保留已加载内容。地图只绘制屏幕附近的节点，完整数据仍可浏览。
- 比较两个存档：先选 A，再选 B；点击文件用原生 VS Code Diff 查看。合并节点默认与第一父提交比较。
- 建分支：在选中节点创建分支，不切换。
- 从这里试一版：创建新分支及独立 Git worktree；通过出现的按钮在新窗口打开。原工作目录保留。
- 切换：选中另一本地分支的节点，在详情中切换，Git 会同步工作文件；工作区需干净。
- 恢复此存档：显示影响文件并请求确认，创建 `gitviz/backup-*` 分支后恢复目标文件树并产生新提交，不删除后续历史。

## 恢复与失败

开发版建分支和试验目录在填写名称后还需最终确认。确认框显示仓库、完整起点/目标提交编号、分支或父目录、差异文件总数及前 8 个文件；建分支/试验目录明确说明原目录不变。确认五分钟内一次有效；确认期间历史引用（包括目标分支）变化时拒绝执行，需要重新预览。取消不会写入 Git 或生成操作记录。旧 0.2.0 包不包含这些更新。

有未提交、未跟踪文件时阻止恢复/切换。恢复还会检查 HEAD 是否改变、Git 操作进行状态、被忽略文件覆盖、稀疏检出及子模块。Git hooks 和签名配置仍然生效；提交失败会保留文件及暂存状态，提示备份分支，供你处理后继续提交。不会用强制 reset 自动丢弃改动。

当前开发源码新增“操作记录与恢复”（旧 0.2.0 包不包含）。可检查每次执行的起点、备份、结果和错误；解决失败原因后，通过“检查并继续提交”与原生确认框继续保留的提交。HEAD、分支、暂存内容和工作文件必须仍符合失败检查点，且没有未跟踪文件或未保存编辑器。取消不增加执行记录；已中断或损坏的记录只供检查。记录保存在当前 worktree 的 Git 元数据中，关闭窗口后仍在；同一工作区可由开发版桌面或 DSH 读取。

## 设置

- `gitviz.historyLimit`：每批数量，默认 300、范围 20–2000；不是历史总数上限。虚线表示未载入的父历史。
- `gitviz.worktreeDirectory`：试验目录。Windows 检测到 F 盘时默认 `F:\Codex\worktrees`；其他环境使用仓库旁的 `gitviz-worktrees`。

历史范围为本机分支、远程跟踪引用、标签和 HEAD 可达的提交；不会自动 fetch。浅克隆会显示提示。仓库引用在加载期间变化时，刷新后重新读取。已用含分叉和合并的 2000、5000、10000 条真实 Git 历史验证分页；更大规模未实测。

本版为桌面/远程 Extension Host 插件，不支持 vscode.dev 虚拟工作区。DSH 与桌面本地入口复用 `src/version-tree/` 地图；各自的写入能力保持原有边界。
