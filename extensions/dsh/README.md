# Gitviz for DeepSeek Harness

Git 存档式版本树：预览节点、比较两个版本、查看逐行差异、创建分支、独立 worktree 和保留历史的恢复。

适配 DSH **0.2.0-rc.2 的 Web profile**，需要本机 Git 与 Node.js 22.12+。仅支持回环地址 http://127.0.0.1 或 http://localhost；远程部署和 Electron 暂不支持。界面为中文，侧栏标题随 DSH 中英语言切换。

## 安装

当前源码构建版本为 0.3.0 开发版，尚未正式发行。启动 `dsh web`，打开侧栏“插件” → “添加插件”，输入 `fisharly-gitviz-dsh-0.3.0.tgz` 的绝对路径，点击“安装”，完成后选择“立即启用”。侧栏将出现 **Gitviz 版本树**。更新旧包时，卸载旧包、安装新包并重启 DSH。

打开面板，选择本机 Git 仓库的绝对路径。面板选择的仓库独立于 DSH 对话工作目录。

## 操作

- 点节点只预览；绿色 HEAD 表示工作文件所在版本。
- 默认先载入 300 个存档，可逐批加载或连续加载到末尾，随时停止；没有 2000 条总数上限。
- 搜索覆盖本机全部可达提交的标题、作者、编号和引用；点击结果会加载并定位到对应节点。地图只绘制视口附近的节点。
- “比较两个存档”或 Shift 点选第二个节点，点击文件查看差异。
- “建分支”保留当前工作文件；“从这里试一版”创建独立目录。
- 切换分支和恢复需要干净工作区；写入均有影响确认。恢复新建提交和备份分支，不删除历史。
- 打开刚创建的试验工作区，仅切换版本树的查看对象；要让 DSH agent 使用它，请在 DSH 中另选该目录。
- Git 钩子、签名和 Git 身份配置仍生效。恢复提交失败时保留备份与已产生的暂存修改，检查 Git 状态后处理。
- 切换或恢复前先保存编辑器内容；插件检查磁盘上的 Git 状态，无法检查其他编辑器的未保存缓冲区。

当前开发源码新增“操作记录与恢复”（旧 0.2.0 包不包含）。展开可查看起点、备份、结果和失败原因；修好身份、签名或钩子问题后，点击“检查并继续提交”，在面板确认后继续。暂存内容、工作文件、HEAD 或分支已变化，以及存在未跟踪文件时会拒绝，不自动覆盖新工作。取消会撤销本次确认票据。重启 DSH 或刷新页面后记录仍可读取；“进行中或已中断”记录不会自动重试或删除锁。

开发版确认信息与桌面、VS Code 的共有操作对齐：显示仓库、完整起点/目标提交编号、分支或父目录、文件总数及前 8 个文件，未展开数量明确提示。创建分支/试验目录列的是目标差异，原目录不变。确认期间目标分支或其他历史引用变化，会拒绝旧票据，需刷新并重新预览；执行请求不能替换已确认的参数。

Windows 试验目录默认 `F:/Codex/worktrees`；其他系统默认 `~/gitviz-worktrees`。插件配置可指定 `initialRepository` 与 `worktreeDirectory`，均为绝对路径。旧 HEAD 会保留在首批窗口内。单文件读取上限 2 MB，大文件差异只显示有界预览。

历史范围为本机分支、远程跟踪引用、标签和 HEAD 可达的提交；不自动 fetch，浅克隆会提示。引用变化时需刷新后继续加载。已验证 2000、5000、10000 条含分叉/合并的真实 Git 历史；更大规模尚未实测。

开发：仓库根目录 `npm run dsh:package`。host.mjs 只接受本机同源 JSON 请求；确认票据绑定仓库、动作和预览状态，5 分钟内一次有效。代码不会读取模型密钥或调用模型。
