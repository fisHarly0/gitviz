# 首次试用记录

目标：请没有参与 Gitviz 开发的人独立走完一次查看、试验和返回，记录真正卡住的步骤。当前仍是开发版；自动测试不能代替本次试用。

## 准备

先确认测试程序对应的提交和 SHA-256，记录 Windows 版本、屏幕分辨率与显示缩放。Windows 桌面需要 Git 和 WebView2，程序、插件、仓库是不同文件，不要把仓库目录当作安装位置。

用一个专门的演示仓库测试；不要要求试用者第一次就对自己的工作仓库执行恢复。演示仓库应有 `main`、一条试验分支、至少一个合并提交和几个内容不同的文本版本，解压后的根目录包含 `.git`。可先让测试者按 [第一次使用](first-use.md) 自行完成安装与打开，观察时不要替他点击或提前解释按钮。

## 任务

给测试者目标，先让他自己决定怎么做。观察者记录首次操作、是否需要帮助及原话。

1. 打开仓库，指出当前实际分支和提交；选择一个旧节点，判断工作文件有没有跟着改变。
2. 找到一个分叉或合并，说明两条路线的关系；折叠、展开和返回当前位置各一次。
3. 从旧节点创建一条独立试验路线，选择目录并打开。说明现在操作的是哪个仓库，原目录有没有变化。
4. 在试验工作区修改文本并提交。桌面使用内嵌编辑器；VS Code / DSH 按宿主编辑流程完成。查看新节点与差异。
5. 返回原仓库，找到刚才的试验目录，并判断“返回”是否撤销了试验中的修改。
6. 关闭并重新打开程序，重新找到原仓库与试验仓库。不要提示当前跨会话返回按钮的限制，先记录是否造成困惑，再解释仓库选择器的用法。

另在一次单独任务中体验恢复：只对演示仓库选择旧节点并阅读确认内容，先取消一次，再执行。问测试者预计恢复后是删除后续历史，还是产生新提交；操作后核对实际结果。不通过诱导提问教会答案。
