# 第一次使用 Gitviz

当前是 **0.3.0 开发版**，尚未正式发行。构建和安装入口见 [工程交付](delivery.md)、[VS Code 插件](../extensions/vscode/README.md) 和 [DSH 插件](../extensions/dsh/README.md)。旧 0.2.0 包不包含本文中的新提示与恢复入口。

## 打开自己的仓库

本地三端都需要 Git。先在终端运行 `git --version`；如果命令不可用，从 [Git 官方安装页](https://git-scm.com/install/) 选择对应系统。安装或修改 PATH 后，完全退出并重新打开宿主，使它读取新的环境。

| 入口 | 打开方式 |
|---|---|
| Windows 桌面 | 在“本机仓库路径”粘贴完整路径并按 Enter，或点击“选择文件夹”；也可拖入仓库文件夹。选择包含 `.git` 的工作目录，linked worktree 也支持。 |
| VS Code | 安装 VSIX，打开仓库目录，在命令面板执行“Gitviz: 打开交互式版本树”。 |
| DSH Web | 安装并启用插件，打开侧栏“Gitviz 版本树”，输入本机仓库的绝对路径。这个选择独立于 DSH 对话工作目录。 |
| 浏览器 | 填写 GitHub 的“所有者/仓库名”或仓库网址，只读打开；本地文件夹需要桌面应用或插件。 |

路径输错时可直接修改后重试。空仓库需要先完成首次提交，再刷新历史。未成功打开仓库时，插件不会将未知状态显示为“工作区干净”。

## 看懂当前位置，再执行操作

**实际位置（HEAD）** 是仓库目前检出的提交；**预览位置** 是你选中的节点。点击节点、比较、搜索、展开或折叠历史，都不会更换仓库目录、切换 HEAD 或改写工作文件。桌面“返回实际位置”退出预览。

- “建分支”创建引用，保留当前工作文件。
- “从这里试一版”创建独立工作目录；在地图中打开它，才更换当前查看的仓库。
- “切换”会同步实际 HEAD、暂存区和工作文件，执行前需确认。
- “恢复此存档”先建备份，再生成内容对应目标版本的新提交，保留后续历史。
- 桌面编辑旧节点时，会先说明并确认创建、切换试验分支；“保存并提交”会写入真实仓库。

地图默认每批读取 300 条，可继续加载或连续读到末尾；这不是总量限制。折叠与定位见 [长历史探索](map-exploration.md)。

## 从旧存档试一版，再返回

1. 选中节点查看提交说明与文件变化。单个节点下方是相对父提交的改动；它不是与当前工作文件的全部差异。VS Code / DSH 可点击“与实际位置比较”，查看 HEAD → 所选节点的已提交内容差异，不包含未提交修改。
2. 只想结束查看时，点击“返回实际位置”。插件会退出比较、清除搜索与局部范围，重新定位 HEAD；不会执行 Git 切换。
3. 点击“从这里试一版”，确认名称、目录和影响后创建独立工作区。原仓库的未提交进度保留，试验目录从选中提交开始。
4. 创建成功后，再明确选择打开。桌面与 DSH 在当前地图打开，并提供“返回上个仓库”；VS Code 在新窗口打开，原窗口保留，切回即可。DSH 地图的选择不会改变对话工作目录。
5. 桌面在 `if-` 试验分支的当前节点也可直接编辑文件。编辑期间需先完成或取消编辑，再返回其他仓库。

返回不删除试验目录，也不撤销试验中的修改或提交。桌面 / DSH 的返回记录仅保留在本次界面会话中，重新启动、重载面板或手动更换仓库后，可通过仓库选择器再次打开需要的目录。

## 无法启动 Git

1. 在终端运行 `git --version`，确认 Git 可执行；同时确认仓库目录仍存在且可访问。
2. VS Code 还需检查设置中的 `git.path` 是否指向有效的 Git 程序。修正后重载窗口；若修改了系统 PATH，则完全退出并重新打开 VS Code。
3. 桌面完全退出后重新打开。DSH 应重启服务，单独刷新网页不会更新服务进程的 PATH。
4. 再打开仓库或点击“重新读取”。保留详细原因，区分程序不存在、目录不存在和权限问题。

这些检查不需要删除 Git 锁、清理工作文件或重建仓库。操作已经开始后失败，则应查看“操作记录与恢复”，按 [失败恢复说明](operation-recovery.md) 检查现场。

## 存档详情或比较读取失败

VS Code / DSH 的“文件变化”区域会保留具体错误，可点击“重试读取详情”或“重新比较”。这些按钮只重新读取所选版本，不提交或切换工作文件。等待第二个比较节点、正在读取、读取失败和文件内容相同分别显示；切换节点或仓库后，旧请求的迟到结果不会替换当前详情。

重试支持键盘操作。地图缩放与窗口尺寸调整保持当前控件焦点；在地图中用方向键选择节点时，焦点跟随选中的节点。

## GitHub 无法打开

公开仓库通常可不填令牌。私有仓库需要有该仓库读取权限的令牌。401 表示令牌未被接受；403 可能是权限或请求额度问题；404 也可能是无权访问，先核对仓库名称与权限。请求过于频繁时稍后重试。

令牌只用于只读 API 请求；浏览器允许会话存储时，在当前标签页保留。不要将令牌放进仓库路径、截图或问题反馈。GitHub 在线图仍有历史数量限制，不等同于本地三端的完整历史地图。

在线模式使用同一套版本地图，可折叠、搜索已读取历史、用方向键选择节点。远程分支是**浏览基准**，没有对应的本机检出状态；“返回远程分支顶端”只结束预览。分支或标签读取失败会列出具体范围，点击“重新读取历史”重试；刷新失败时会标明保留的是上次结果。

详情失败可单独“重新读取详情”。GitHub 没有提供文本差异时，界面会说明原因可能是二进制文件或差异过大，而不是显示空白并暗示没有变化。文件列表还有下一页时会提示当前列表不完整，可通过原提交链接继续查看。[GitHub API 的提交和差异限制](https://docs.github.com/en/rest/commits/commits#get-a-commit)。

## 更新与验证范围

桌面、VS Code 和 DSH 的安装、升级及重启差异见 [升级说明](upgrade-testing.md)。更新 DSH 插件后重启服务；本地反复构建同版本包时，应使用不同的包文件路径，避免包管理器复用先前内容。

Windows 原生桌面、实装 VSIX 和 DSH Web 已验证缺少 Git 的提示与恢复；桌面另验证路径修正、键盘打开、空仓库、只读预览及中文编辑流程。GitHub 模式在 VS Code Integrated Browser 中验证真实公开仓库，以及受控 HTTP/断网故障和重试；这不代表已验证真实私有仓库权限或穷尽 GitHub 服务故障。Linux/macOS 原生界面及全面可访问性审查尚未完成。首次使用测试记录见 [首次使用交接](../memory/handoff-2026-10-05-first-use.md) 和 [GitHub 只读交接](../memory/handoff-2026-10-05-github-readonly.md)。
