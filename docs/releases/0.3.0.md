# 0.3.0 发布说明草稿

状态：**开发验证中，尚未正式发行**。最终安装包、支持平台及校验和需在公开产品清单完成后确认；本文件不代表已发布 Release。

## 相比原 0.2.0

- 三端地图增加连续历史折叠、分支/标签查找与定位、附近节点探索。搜索、比较和键盘移动仍指向真实提交，浏览不切换工作文件。
- VS Code/DSH 的详情和比较失败提供就地重试，区分读取失败与没有文件变化；地图布局调整不再抢走其他控件的键盘焦点。
- 桌面编辑器及语言 worker 随包提供，首次编辑本地文本无需下载 CDN 资源；编辑器仍按需加载，包体积相应增加。
- 桌面切换和编辑改用真实 Git 同步 HEAD、index 与工作目录，写入经过预览和一次性确认。建分支保留当前位置，试验使用独立 worktree，恢复创建新提交并保留备份。
- 三端持久操作记录说明实际结果与失败现场。可对符合检查点的失败提交重新确认并继续，不自动覆盖后来产生的修改。
- 增加稀疏检出、隐藏 index 标记、子模块状态、工作树占用、过期引用及提交结果检查。Git 超时或输出异常不冒充成功。
- VS Code/DSH 已确认且移交的操作由独立进程执行，关闭面板后可在操作记录检查结果。桌面正常关闭保护未保存草稿及执行中的操作。
- 统一版本、自动 CI、插件包完整性/重复构建校验，构建产物关联源提交并附 SHA-256。

## 更新准备

关闭正在运行的 Gitviz 写入并确认记录结果。VS Code 安装新 VSIX 后重新加载窗口；DSH 安装新 tarball 后重启服务端，仅刷新页面不能替换已缓存的 Git 模块。桌面退出旧进程后再更新程序。

三端使用相同的 v1 操作记录格式，记录按 worktree 保存在 Git 元数据中；升级不删除记录或未完成现场。最终包的实际安装、旧版升级与重启恢复仍须专门验收，不能仅按上述说明推断通过。

## 已知边界

- 大历史已覆盖含分叉/合并的 2000、5000、10000 条真实提交；无总数硬上限，更大规模尚未实测。只读取本机可达历史，不自动 fetch。
- GitHub 在线入口复用共享地图，但仍是只读和有限范围浏览：最多读取前 100 个分支、100 个标签及每分支 100 条提交，搜索限已读取范围。DSH 面向本机 Web profile，地图仓库与对话工作目录独立。
- 确认和锁不能禁止外部 Git 工具修改仓库。失败可能已经产生提交或文件改动，需检查实际结果；断电、强杀整个执行进程树不保证操作完成。
- 当前 Windows 三端原生交互有验证证据；Linux/macOS 原生 UI、安装与升级不得仅以 CI 编译/后端测试推定支持。
- 正式发行前仍须完成 [公开产品验收](../../spec/modules/public-product.md)，包括首次使用、支持平台确认和最终安装包验收。Windows 三端原生并发已验证，桌面刷新历史会同步更新操作记录。当前构建没有代码签名或公证保证。

最终发布时填入：干净源提交、各平台支持状态、安装包链接与 SHA-256、已通过的安装/升级记录。当前开发流水线见 [工程交付说明](../delivery.md)。
