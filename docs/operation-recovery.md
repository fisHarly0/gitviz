# 操作记录与失败提交恢复（开发版）

适用于当前源码构建的桌面、VS Code 和 DSH。已保留的旧 0.2.0 包没有这套能力；正式版本与升级验收仍在进行。

## 如何继续失败的提交

1. 展开右侧“操作记录与恢复”，查看未完成记录的开始位置、备份、文件路径和错误。恢复失败不会自动丢弃已经产生的文件及暂存修改。
2. 根据错误解决 Git 身份、签名或钩子问题。先用 Git 检查状态；不要为了通过校验而丢弃后来新增的工作。
3. 桌面先结束内嵌编辑，再使用记录的“检查并继续提交”。结束编辑只关闭编辑缓冲，已经写到磁盘和暂存区的失败提交内容会保留。VS Code 会阻止包含未保存编辑器的仓库继续；DSH 无法检查其他编辑器的内存缓冲。
4. 核对仓库和确认内容后执行。成功会显示完成记录与实际新提交，原备份保留。身份、hooks 和签名继续由 Git 执行。

继续操作要求：仍在原 HEAD 和原分支，备份引用未变化，暂存内容等于失败检查点，工作文件与暂存区一致，没有未跟踪文件或进行中的合并/变基等操作。每次先只读预览，确认后再检查。任何条件不满足就停止，不自动 add、reset 或 stash；可在检查并保留自己的新工作后，通过 Git 手动处理。

取消确认不执行、不增加尝试次数。已经成功的记录不能再次提交。“进行中或已中断”可能表示另一个宿主仍在执行，或程序意外退出；需检查实际 Git 状态，不自动重试或删除锁。钩子在提交中改变结果时，会报告差异并保留实际结果供检查。

## 保存在哪里

记录位于 `git rev-parse --absolute-git-dir` 对应目录的 `gitviz/operations/` 下，不作为仓库文件提交。关联 worktree 使用各自的 Git 目录，记录相互独立。同一个 worktree 的三端读写同一种 JSON v1 格式，可跨宿主继续符合条件的失败提交。

记录包含动作参数、仓库路径、开始/更新时间、原 HEAD/分支、备份或输出路径、结果、错误和尝试次数；不保存编辑正文。不要把记录当作工作文件备份。当前不会自动清理旧记录，界面按页读取；损坏、超出大小限制或版本不支持的记录显示错误，不能继续执行。

## 当前边界

- 仅支持保存/恢复在提交前留下有效检查点的失败。操作未到检查点、崩溃、人工改过现场等情况不提供自动续接。
- Gitviz 的锁用于协调同一 worktree 的三端写入；外部 Git 命令和编辑器不会遵守这个锁，操作期间仍应避免并发修改。
- Git 钩子可能执行自己的外部操作，记录不会撤销这些副作用。
- 桌面正常关闭已有草稿和执行保护；三端 Git CLI 已加入超时、输出上限和清理失败时的写入暂停。看到“无法确认 Git 及其子进程已停止”时，先按 [异常进程说明](git-processes.md) 检查现场，再考虑继续。宿主强制退出、断电和插件关闭仍待验收。
