# 操作执行后的结果检查

适用于当前源码构建的桌面、VS Code 和 DSH。操作开始后，外部 Git 工具或用户 hook 仍可能改变仓库；Git 命令退出成功并不总意味着结果符合确认内容。

Gitviz 在返回成功前检查：

- 切换和桌面试验分支：实际分支、目标提交与工作区状态。
- 新建分支：新引用指向所选提交，原 HEAD/分支不变。
- 独立 worktree：新目录指向所选提交和新分支，原 HEAD/分支不变。
- 保存、恢复和继续提交：新提交位于原分支，唯一父提交是确认时的起点，tree 等于提交前检查点；检查工作区和已有备份引用。

提交前也会重新检查现场。建立恢复备份后、改写工作文件前，再核对 HEAD/分支与干净状态；恢复后的暂存 tree 必须等于目标存档。桌面保存不允许暂存区混入其他文件，编辑文件也必须仍是刚保存的内容。若这一阶段发现混入内容，会保留文件和 index，停止 commit，并且不提供该混入检查点的“继续提交”。

## 看到“Git 操作结果与确认不一致”时

这次操作可能已经创建提交、切换分支或创建工作目录。先刷新地图，展开操作记录，核对开始位置、实际 HEAD/分支、备份和新工作区路径，再用 Git 检查文件及暂存差异。不要立即重复同一操作。

记录标记为失败，表示整个操作未达到确认的结果，不代表 Git 什么都没有做。Gitviz 不会为了恢复画面上的旧状态而自动 reset、删除新分支/worktree 或丢弃文件。已产生的提交可结合实际引用和 reflog 检查；备份并不涵盖 hook 自己的外部副作用。

符合原检查点且仍在原起点的普通提交失败，仍可使用原有继续入口。HEAD 已变化、检查点无效或文件不同的情况会拒绝继续；不要为了通过检查而丢弃后来的工作。

## 验证范围

Windows 测试使用真实 reference-transaction、post-checkout、post-commit、post-index-change hooks，覆盖建立备份时移动 HEAD、切换后移动 HEAD、提交后换成相同 tree 但父提交不同的提交、worktree hook 修改文件，以及恢复/编辑暂存期间混入外部文件。检查失败后保留实际文件、引用、工作目录和恢复前备份。

这些检查不是跨程序的原子事务。外部 Git 不受 Gitviz 操作锁控制，检查结束后仍可能再次修改仓库；操作期间应避免并发编辑和 Git 写入。本批不承诺消除所有竞态，也不替代宿主退出与其他平台验收。
