# 在长历史中找存档

开发版桌面、VS Code 和 DSH 共用这些地图功能；重新构建或安装开发版后生效，旧 0.2.0 包不会自动更新。GitHub 在线只读图仍使用原有界面。

## 折叠连续历史

地图默认把至少三个普通连续提交收成一段。卡片显示数量及两端编号，点击展开；“重新折叠”收回展开的段，“显示每个存档”恢复逐个显示。

实际 HEAD、分支和标签、根节点、分叉、合并以及历史边界保持为真实节点。选中、比较或搜索到的提交自动显露。折叠只改变显示方式，完整提交及父关系仍在内存中；摘要卡片不能作为 Git 操作目标。

方向键沿真实提交顺序移动，包括折叠段中的提交；Home / End 到当前显示范围的两端。展开段会把键盘焦点移到其中最新提交，不会自动切换工作文件。

## 分支与标签

点击“分支与标签”，在原地图区域内按名称或提交编号检索引用。点击条目返回地图并定位预览；未加载的目标会逐批加载至该提交，仍可通过原有进度栏停止。“返回地图”或 Esc 关闭引用列表，焦点回到入口按钮，保留原地图位置。

列表每次最多展示 30 项，可以继续显示更多。远程分支来自本机已有引用，不会自动 fetch。HEAD 的实际位置与当前预览继续分别标识。

## 节点附近

选择一个真实提交，再点“只看节点附近”。范围按父/子连接计算，可选择前后 1、2、4、8 步；合并提交可以连到多条路径，因此节点数不一定是步数的两倍。

探索中心保持固定。选择附近另一节点后，可点击“以当前选择为中心”；“退出附近视图”恢复全部已加载历史。搜索和双节点比较期间暂停附近视图，避免目标被范围遮挡。

附近视图只使用已经加载的历史，虚线明确标出范围外或尚未加载的父提交。扩大步数不会代替历史加载；需要更早提交时，先加载历史或通过搜索、引用定位。

## 验证范围

`npm test` 检查投影的完整提交覆盖、合并边、引用/选择保护与局部范围。`npm run history:test` 在 2000、5000、10000 条真实 Git 历史中核对分页、搜索、父边及折叠后的连接；没有总提交数硬上限，更大规模尚未实测。

`tests/map-exploration-smoke.cjs` 用独立配置中安装的 Windows 桌面、VS Code 与 DSH 检查一万条历史。需提供绝对 scratch 路径 `GITVIZ_DESKTOP_TEST_ROOT`（内含合成仓库及 `fixture.json`）、宿主 `GITVIZ_TEST_HOST=desktop|vscode|dsh` 和 `PLAYWRIGHT_CORE_PATH`，并先启动相应原生宿主及 CDP。默认桌面端口 9248、插件端口 9235；DSH 使用 VS Code 集成浏览器中的本机服务 3087。

fixture 包含 `root`、`first`、`target`、`head`：目标仓库必须位于 scratch 内，包含一万条提交、指向最早提交的 `origin-point` 标签，以及位于历史中部的搜索目标。测试只浏览历史，并核对前后 HEAD、工作区和引用保持一致；不在真实项目上运行写入测试。它不替代其他平台或正式安装升级验收。
