# 插件关闭、停用与执行中的操作

适用于当前源码构建的 VS Code 和 DSH 开发版。旧 0.2.0 包不会自动获得这些更新；正式版本和升级验收尚未完成。

## 关闭后发生什么

- **尚未确认或尚未交给执行进程**：关闭 VS Code 旧面板或停用插件后，迟到的确认不能开始写入。DSH 停用会使票据失效，已经开始上传、停用后才收到完整正文的请求也会拒绝。
- **已经确认并交给执行进程**：Git 操作会继续。关闭面板、退出 VS Code、停用 DSH 插件或断开浏览器连接，都不等于取消已经接受的 Git 操作。
- **再次打开**：刷新历史并检查“操作记录与恢复”。实际执行仍遵守仓库锁；执行中不能从另一个 Gitviz 宿主开始新的写入。VS Code 在旧面板操作结束时会通知重新打开的面板刷新。

恢复依然创建备份及新提交，Git 身份、签名、hooks、预检、超时和执行结果核对仍然生效。普通失败保留现场；是否可继续取决于有效检查点，见 [恢复说明](operation-recovery.md)。

## 实现与边界

两个插件在最终确认后，将宿主持有的一次性计划通过父子 IPC 交给独立 Node 进程。它不开放监听端口、不把请求写到磁盘，也不通过 shell 拼接操作参数。每个进程只执行一项操作；锁使用执行进程的 PID，完成或失败后写入持久记录并退出。

宿主关闭与任务接收同时发生时，可能没有成功交接。若界面没收到结果，不能据此判断成功或失败；重新打开后检查记录及实际 Git 状态。不能自动重放旧确认。

强杀整个进程树、强杀执行进程、执行进程崩溃或断电仍可能留下修改、锁和“进行中或已中断”记录。此类记录不会自动继续或删除锁。先检查实际进程与 Git 状态，按 [异常进程说明](git-processes.md) 处理。外部 Git 不遵守 Gitviz 的锁，不能把独立进程当成跨程序原子事务。

## 验证范围（Windows，2026-10-05）

| 场景 | 证据 |
|---|---|
| 真实 hook 执行时正常结束或强制结束测试宿主，worker 继续完成 | Node 与 VS Code Electron Node 模式均通过；检查父提交、目标 tree、干净状态、记录、锁及 worker 自行退出 |
| 关闭旧 VS Code 面板后重开，迟到原生确认返回；扩展停用后确认返回 | 宿主 API 接缝测试使用真实 Git，均不创建分支或记录；这两项不是原生 UI 测试 |
| DSH 停用期间的延迟请求正文 | 真实 HTTP 测试拒绝，无写入 |
| DSH 恢复 hook 执行时停用 | 真实 HTTP 测试中已经接受的恢复完成，后续请求拒绝 |
| 已安装 VSIX，关闭并重开版本树，随后退出整个 VS Code | 原生确认及真实 Git hook；退出后 worker 仍在，放行后恢复完成，核对父提交/tree/工作区/记录/锁 |

仅终止测试宿主 PID 的测试不等于杀死整个进程树。DSH 本批验证到 HTTP handler 与实际执行进程；未重新进行 DSH 原生插件管理页停用测试。Linux/macOS、远程 Extension Host 尚未运行生命周期验证，桌面 Tauri 沿用独立的 [窗口关闭保护](desktop-close.md)。

回归入口：`npm run extension:test`、`npm run dsh:test`。原生脚本 `tests/vscode-lifecycle-smoke.cjs` 必须使用隔离 VS Code profile、已安装开发 VSIX、显式指定的合成仓库与 CDP 连接；只操作测试仓库。脚本需要测试 profile 中的 `Gitviz Fixture Quit` 命令调用真实 `workbench.action.quit`，该命令不属于产品插件。

设计决策：[插件宿主生命周期](decisions/2026-10-05-plugin-lifecycle.md)。
