# 写入前检查（开发版）

三端在预览和执行时都会检查仓库状态。确认框打开之后发生变化，执行仍可能被拒绝；取消或预检拒绝不会创建备份、操作记录或提交。

| 仓库状态 | 当前行为 |
|---|---|
| 稀疏检出 | 切换、整树恢复、桌面编辑写入、继续提交均拒绝；创建分支和独立 worktree 仍可用 |
| index 含 skip-worktree／assume-unchanged | 修改当前工作文件或继续提交前拒绝，提示先检查标记；不自动清除 |
| 子模块有修改或未跟踪文件 | 需要干净工作区的操作拒绝；即使 Git 配置隐藏子模块变化，也会检查 |
| 当前版本或恢复目标包含子模块 | 整树恢复在预览时拒绝；暂不提供子模块整树恢复 |
| 正在合并、变基、cherry-pick、revert 或 sequencer 操作 | 写入预览和执行均拒绝，包括 linked worktree；先完成或中止已有操作 |
| 恢复会覆盖被忽略的文件 | 在预览时提示冲突文件，保留文件，需先自行保存或移走 |
| Git 身份无效 | 恢复预览时报告 Git 错误，尚不创建备份或修改文件 |

稀疏检出和 index 标记可能是你有意设置的。先保存并检查实际文件，再使用 Git 处理；不要仅为让 Gitviz 通过检查而丢弃修改。创建分支只增加引用，独立 worktree 新建目录，原工作目录保持不变。

这套检查不替代 Git 自己的权限、锁、hook 和 worktree 占用检查，也不能锁住其他 Git 工具。操作执行期间仍应避免从其他编辑器或终端并发改仓库。子模块内的独立历史和递归检出不是本批新增能力。

Windows 真实仓库回归覆盖稀疏检出、隐藏文件标记、配置为忽略变化的本地子模块，以及 linked worktree 的六种进行中状态。操作被拒绝后核对 HEAD、文件/index 和操作记录；Linux/macOS 与宿主退出覆盖仍待完成。
