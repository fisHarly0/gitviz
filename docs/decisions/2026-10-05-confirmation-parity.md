# 三端操作确认的一致性

基线 main / aa0d098，工作树干净。公开交付 P1 的当前模块只处理预览与执行绑定及确认信息；进程超时、宿主退出、地图和发行仍保留在完整清单。

- Node GitService 生成结构化预览，字段与桌面已有 expected/target/branchName/directory/files/impact 对齐；VS Code 和 DSH 使用同一份预览与格式化文本。列出仓库、当前 HEAD/分支、目标 OID、分支/父目录、全部差异文件数量和有限文件列表；原目录不变的动作明确区分目标差异与实际写入。
- VS Code 建分支和 worktree 收集名称后再做最终确认；恢复/切换/继续提交也统一读取预览。DSH 保留一次性五分钟票据，服务端保存计划，客户端不能替换计划参数。
- 预览绑定仓库历史 revision，读取前后核对；执行在现有互斥和仓库 guard 内重复核对，拒绝确认期间外部改变目标分支引用的操作。取消不写 Git 或操作记录；失败记录和恢复契约不变。
- 桌面沿用结构化预览，修正 revision 的采集顺序：先记录历史版本，再读取预览并核对历史未变化，避免把旧目标说明与新引用版本绑定在一起。不引入新弹窗系统或改变 Git 写入方式。
- 验证使用 F 盘合成仓库：预览字段、只读、目标移动拒绝、一次性/过期、继续检查点和既有 DSH/Node Git 回归。宿主 UI 及打包需要验证并明确区分与后端证据，不用协议测试冒充实装。
