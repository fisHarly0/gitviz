# 三端操作记录与失败恢复

基线 main / 1b93101，工作树干净。公开交付 P1 的下一批：持久记录已执行动作，并为提交失败提供安全的继续入口。三端范围不变。

## 数据和执行边界

- 每个 worktree 的实际 Git 目录下存放 `gitviz/operations/<id>.json`，同一 JSON v1 格式供 Rust 和 Node 读写。记录动作参数（不含编辑正文）、开始/更新时间、原位置、备份/输出路径、完成位置、错误和尝试次数。按 ID 分页读取，损坏记录可见而不能执行。
- 元数据目录与记录不经过符号链接/Windows 重解析点；文件大小有界，更新采用同目录临时文件与原子替换。操作记录不成为任意文件访问接口。
- Gitviz 写操作使用各 worktree 同名互斥锁；记录写入成功后才开始修改。取消确认不创建操作记录。
- 保存/恢复在提交前记录预期 index tree。失败后保留现场。继续提交要求 HEAD/分支仍等于开始位置、index 完全等于检查点、工作文件与 index 一致、没有未跟踪文件或进行中的 Git 操作。钩子、签名和身份检查继续生效；任何差异都要求用户先处理，不自动 reset/stash。
- 继续操作仍先预览并明确确认，再复查；成功后记录最终提交。崩溃留下的 running 记录仅供检查，不凭记录自动删除锁或推断可以继续。
- 操作记录在宿主重启后仍可查看；桌面编辑未结束前不能继续其他提交，避免丢弃新的内存编辑。

## 验收

真实合成 Git 仓库覆盖：失败 hook、去除问题后的继续提交、重复继续拒绝、外部 HEAD/index/worktree/untracked 变化拒绝、关联 worktree 记录隔离、跨实现格式、记录损坏/链接拒绝、只读预览与取消。宿主接口及界面验证后再宣称三端流程完成；缺少的验证如实记录。保留完整 P1/P2/P3 清单。
