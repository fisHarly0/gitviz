# 原生失败流程验收

基线 main / 2aa19e4，工作树干净。继续公开产品交付 P1，不修改地图或缩减三端范围。

1. 从当前源码重建 Windows 桌面 exe，插件使用已验证且代码与当前基线一致的 lifecycle 开发包；按安装模块哈希核对，不能用旧进程冒充新版。
2. 仅在 F 盘隔离 profile 和合成仓库测试。串行启动原生宿主；复用已有真实 hook 失败/恢复脚本，增加 Git 锁或 worktree 占用等执行失败的 UI 检查，以及 DSH 插件管理页停用期间的已确认操作。
3. 通过用户界面发起操作，不伪造 Git 返回值、扩展消息或 Tauri 操作响应。Git CLI 仅准备 fixture、制造明确外部竞争和验证结果。测试安装配置只在隔离目录生效。
4. 失败需清楚显示并保留实际 HEAD/index/worktree、备份和记录；可继续的失败检查点要能在修复原因后继续。取消/迟到确认不写入。已经交接的操作在 DSH 停用后完成并留下记录，再次启用可查看。
5. 遇到产品缺陷做最小修复并对相关路径回归。记录本轮实际覆盖和未验证项，不把 Windows 或 API 测试当作跨平台、原生 UI 或正式发行证据。

桌面实机发现：继续恢复成功后，分支栏仍显示此前 worktree 占用导致的“分支未切换”。分支栏按仓库与成功恢复 revision 重建，和已有存档动作反馈使用同一边界；失败记录继续保留，不能在失败后仅因 HEAD 变化就隐藏异常。原生回归新增成功恢复后无过时警告的断言。
